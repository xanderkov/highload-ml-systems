## 0. Крючок: «мы же ничего не писали»

Классический способ масштабировать Python-сервис — запустить несколько воркеров-процессов. Чтобы не грузить тяжёлые данные в каждый воркер, их загружают один раз в родителе, а потом делают `fork`: страницы памяти у процессов общие, копия не нужна.

Проверим на «токенайзере» — словаре примерно на миллион строковых ключей.

- Родитель строит словарь и делает `fork` на 4 воркера.
- Воркеры данные только читают: берут значения по ключам и складывают.
- Ключи воркер собирает заново из строк, словарь при этом не меняется.
- На графике — PSS каждого процесса: его доля в разделяемых страницах плюс его личные страницы. Сумма PSS по процессам — честная оценка занятой памяти.

```benchmark id=fork-pss lang=python
harness: fork_pss
source: snippets/fork_pss.py
x_label: время, с
y_label: PSS, МиБ
title: PSS воркеров после fork
```
