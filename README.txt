Высоконагруженные ML/DL системы
Почему мы используем Triton

Интерактивный курс о том, почему сервис с моделью на Python упирается под
нагрузкой не в модель, а в рантайм, протокол и обработку запросов по одному,
и что из этого снимает Triton Inference Server. Каждую проблему курс сначала
замеряет у вас на машине, потом чинит руками.

Запуск

1. Установите и запустите Docker с Docker Compose
   (например, Docker Desktop на Windows или macOS).
2. Откройте терминал в папке курса, где находится docker-compose.yml.
3. Выполните:

   docker compose up --build

4. Откройте http://localhost:18080
   Откроется главная страница курса со всеми разделами.

Первый запуск требует интернета для загрузки образов и зависимостей.
Python, Node.js и PyTorch на компьютере устанавливать не нужно.
Образы собираются под архитектуру компьютера, без принудительной эмуляции.
В образ runner входит PyTorch (CPU), поэтому первая сборка заметно больше
и дольше обычной. Для раздела «Triton» собирается образ triton на основе
официального образа NVIDIA nvcr.io/nvidia/tritonserver — это около 13 ГБ
на диске и самая долгая часть первого запуска. Для раздела «LLM» в образ
runner добавляются сервер llama.cpp (ghcr.io/ggml-org/llama.cpp) и модель
Qwen2.5-0.5B-Instruct в формате GGUF с huggingface.co — ещё около 0,7 ГБ.

Если docker compose падает на загрузке nvcr.io/nvidia/tritonserver с
ошибкой 403 Forbidden, реестр NVIDIA недоступен из вашей сети (так бывает
в некоторых странах). Нужен VPN или прокси для доменов nvcr.io и nvidia.com
на время первой сборки; потом образ хранится локально.

Требования

В Docker должно быть доступно хотя бы 8 ГиБ памяти (runner — до 3 ГиБ,
Triton — до 4 ГиБ), не меньше 4 процессоров и около 20 ГБ места на диске.
Серверу Triton отданы процессоры 1–3, другой набор задаёт переменная
TRITON_CPUS (например, TRITON_CPUS=4-6 docker compose up). Задания с несколькими воркерами и нагрузочные замеры
(разделы «Python как рантайм сервиса» и «Наивный сервис и свой батчер»)
на меньшем числе процессоров покажут сообщение вместо результата.
Время замеров зависит от компьютера и выделенных Docker ресурсов.
Тяжёлые блоки запускайте по одному: одновременные запуски делят общий
лимит памяти runner'а и искажают замеры друг друга.

vLLM (необязательно)

Один блок раздела «LLM» меряет сервер vLLM. По умолчанию он не запускается:
ему нужно около 6 ГиБ памяти (в Docker тогда должно быть доступно не меньше
12 ГиБ), а быстрый режим bf16 работает только на процессорах с AVX-512.
На процессорах без AVX-512 курс vLLM не проверял. Чтобы запустить vLLM,
остановите Triton (они делят одни процессоры):

   docker compose stop triton
   docker compose --profile vllm up -d vllm

Первый старт скачивает модель с huggingface.co (около 1 ГБ) и занимает
пару минут. Вернуть всё как было:

   docker compose --profile vllm stop vllm
   docker compose start triton

Остановка

Нажмите Ctrl+C, затем при необходимости выполните:

   docker compose down

Запуск в фоне:

   docker compose up --build -d

Если порт 18080 занят, создайте рядом с docker-compose.yml файл .env:

   COURSE_PORT=18081

После запуска откройте http://localhost:18081
