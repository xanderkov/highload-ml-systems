# Своя айдентика курса: отделение от CPU-курса и новый дизайн

Дата: 2026-11-07
Статус: дизайн согласован в обсуждении, ожидает ревью спеки

## 1. Контекст и задача

Курс начинался как продолжение CPU-курса коллеги (импорт `7c5b1b7 chore:
import cpu-course as-is`): от него остались раздел `01-cpu-cache`, связанный
с ним код платформы, название «Оптимизация программ / Оптимизация инференса»
и визуальное направление (тёмная монохромная тема, артборды «лабораторного
журнала» в `docs/design/`). CPU-курс был идеей, а курс должен стать своим.

Подпроект делает две вещи:

1. **Отделение.** Убрать раздел про CPU-кэш и всё, что нужно только ему;
   курс начинается с раздела «Python как рантайм сервиса».
2. **Новый дизайн.** Светлая современная техническая документация (в духе
   Stripe/Vercel Docs) на Tailwind CSS, каркас в три колонки.

Название курса: **«Высоконагруженные ML/DL системы»**, подзаголовок
**«Почему мы используем Triton»**.

Доделка раздела `30-naive-service` (задачи 3–6 плана
`2026-11-01-naive-service-section.md`) в этот подпроект не входит и идёт
параллельно; её новые блоки получают новый стиль автоматически.

## 2. Границы

Входит:

- удаление раздела `content/01-cpu-cache` и кода, используемого только им (§3);
- ребрендинг: шапка, `<title>`, главная, README;
- новое введение раздела 20 без мостика из CPU-части;
- Tailwind CSS v4 в сборке образа `web`, новые шаблоны, перевод разметки JS
  на утилитарные классы (§4);
- удаление `docs/design/` (артборды прежнего направления).

Не входит:

- изменения содержания разделов 20 и 30, кроме введения раздела 20 и
  удаления ссылок на CPU-раздел;
- изменения runner'а сверх удаления C-поддержки и `cache_info`.

## 3. Отделение от CPU-курса

### 3.1. Удаляется

- `content/01-cpu-cache/` целиком.
- Viz, используемые только CPU-разделом: все модули `web/static/viz/`, кроме
  `cow-pages.js` и `pymalloc-arenas.js` (раздел 20). `cpu-overlap.js`
  удаляется: используется только в `01-cpu-cache`.
- Блоки и ветки JS, нужные только CPU-разделу (например,
  `blocks/index-tutorial.js` и ветки ассемблера в `exercise.js`), — если grep
  подтверждает, что разделы 20/30 их не используют.
- Сбор сведений о кэше хоста: `scripts/cache-info.py`,
  `runner/app/cache_info.py`, его эндпоинт и использование в `runner/app/main.py`
  и `web/app`, том `./.runtime:/host-info` в `docker-compose.yml`, шаг
  `python3 scripts/cache-info.py` в `make up`, `docs/cache-info.md`, абзац про
  `.runtime` в README.
- Поддержка C в runner: компиляция `bench.c`, разбор ассемблера
  (`scripts/bench-asm.sh`, `runner/tests/test_matrix_asm.py`, фикстуры
  `runner/tests/fixtures/harness/{sumtest,sweeptest}`), GCC в образе runner,
  если он нужен только для этого. tmpfs `/work` с `exec` остаётся, только если
  его использует что-то кроме скомпилированных бенчмарков; иначе — без `exec`.
- Режим Ace `mode-c_cpp.js` в вендоре.
- `TODO.md` (тема про индирекцию указателей относится к CPU-курсу).
- `docs/design/`.

Правило: перед удалением каждой сущности — grep по `content/20-*`,
`content/30-*`, `web/`, `runner/`, `scripts/`, `Makefile`; удаляется только то,
на что не ссылается ничего живое. Тесты, проверяющие удалённое, удаляются
вместе с ним; тесты общих механизмов, использовавшие CPU-раздел как пример,
переводятся на раздел 20.

### 3.2. Ребрендинг

- Шапка и `<title>`: «Высоконагруженные ML/DL системы»; на главной —
  подзаголовок «Почему мы используем Triton».
- README переписывается: название курса, запуск, требования (≥ 4 CPU в Docker
  для заданий разделов 20 и 30, память), без упоминаний `cpu-course`, GCC,
  Numba, `.runtime`.
- Введение раздела 20 становится вводом в курс: о чём курс (путь от Python-
  рантайма через наивный сервис к Triton), принцип «сначала замеряем боль,
  потом чиним» — без ссылок на CPU-кэш.
- Каталоги разделов не переименовываются (`20-`, `30-`); порядок задаёт `order`,
  номер в навигации — позиция в списке.

## 4. Новый дизайн

### 4.1. Сборка CSS

- Tailwind CSS v4 (`tailwindcss@4`, `@tailwindcss/cli@4`,
  `@tailwindcss/typography`) ставится в существующую стадию `vendor`
  Dockerfile `web`; там же выполняется `npx @tailwindcss/cli -i
  static/src/app.css -o /out/app.css --minify`. Результат копируется в
  `/app/static/` вместе с прочим вендором.
- Источник — `web/static/src/app.css`: `@import "tailwindcss"`,
  `@plugin "@tailwindcss/typography"`, `@theme` с токенами (§4.2), `@source`
  на `web/app/templates`, `web/app/render.py`, `web/static/**/*.js`.
- Для стадии `vendor` контекст сборки должен включать шаблоны, `render.py` и
  JS: `COPY` нужных путей перед запуском CLI.
- Классы собираются только из полных строковых литералов: в JS и Python
  запрещено склеивать имена классов из частей (`"bg-" + color`). Для
  состояний — словари с полными именами классов.
- Небольшой слой `@layer components` допустим для повторяющихся составных
  элементов (карточка блока, кнопка, callout), чтобы JS не дублировал длинные
  списки утилит. Остальное — утилиты в разметке.
- Чужие компоненты (Ace, uPlot, KaTeX) оформляются через их CSS плюс
  точечные переопределения в `app.css`; их внутренняя разметка не меняется.
- Старый `web/static/style.css` удаляется. Шрифты вендорятся через fontsource:
  `@fontsource-variable/inter` и `@fontsource/jetbrains-mono` (уже есть), с
  кириллическими подмножествами; внешней сети страница не требует.
- `asset_prefix` (сброс кэша статики) применяется к собранному `app.css`.

### 4.2. Токены

Светлая тема по умолчанию, тёмная — по `prefers-color-scheme: dark`.
В верхней полосе — переключатель «как в системе / светлая / тёмная»
(`data-theme` на `<html>`, выбор в `localStorage` `course.theme`, применяется
скриптом в `<head>` до отрисовки). Тёмная тема нейтральная, без синевы
(изменено после просмотра автором 2026-11-07). Токены — CSS-переменные в `@theme`,
переопределяемые в тёмной теме:

| Токен | Светлая | Тёмная |
| --- | --- | --- |
| фон | `#ffffff` | `#0a0a0a` |
| поверхность (карточки, код) | `#f8fafc` | `#171717` |
| линии | `#e2e8f0` | `#262626` |
| текст | `#0f172a` | `#e5e5e5` |
| приглушённый | `#64748b` | `#a3a3a3` |
| акцент (индиго) | `#4f46e5` | `#818cf8` |
| зачтено | `#16a34a` | `#4ade80` |
| ошибка | `#dc2626` | `#f87171` |
| предупреждение | `#d97706` | `#fbbf24` |

Шрифты: Inter (текст, интерфейс), JetBrains Mono (код, числа, метрики).
Цвета серий uPlot читаются JS из CSS-переменных (`getComputedStyle`), а не
зашиты в код. Тема Ace: `github` в светлой, `github_dark` в тёмной, выбор по
`matchMedia`.

### 4.3. Каркас страницы раздела

Три колонки:

- **Левая (≈ 260px)** — навигация по курсу: название курса, список разделов с
  прогрессом по заданиям (`N из M`, данные из `progress.js`), у текущего
  раздела раскрыт список подглав. Готовящиеся разделы (Triton, LLM) в
  навигации не показываются.
- **Центральная (до ≈ 720px текста)** — статья; проза через `prose`
  (typography) с настроенными цветами; блоки (задание, замер, эксперимент,
  viz) могут быть шире текста — до ширины колонки.
- **Правая (≈ 220px)** — «На этой странице»: подглавы и их подзаголовки,
  подсветка текущей через `IntersectionObserver`, отметка ✓ у подглав, где все
  задания зачтены.
- Внизу статьи — пейджер на соседние разделы.

Адаптивность: < 1200px — правая колонка скрыта; < 860px — левая колонка
сворачивается в выдвижную панель по кнопке «☰» в верхней полосе; без
горизонтальной прокрутки страницы (широкие блоки кода прокручиваются внутри).

### 4.4. Главная

Название и подзаголовок, абзац «о чём курс и как он устроен» (замер → боль →
решение → Triton), карточки разделов: номер, название, одна строка описания
(новое необязательное поле фронтматтера `summary`), прогресс по заданиям.
После существующих разделов — карточки «скоро»: «Triton Inference Server» и
«LLM-сервинг» (без ссылок).

### 4.5. Компоненты

- **Блоки** (задание, замер, эксперимент, сравнение): карточка — рамка
  `линии`, скругление 8px, фон `фон`; шапка с типом блока («Задание 1»,
  «Замер», «Эксперимент») и статусом справа; код в редакторе Ace на фоне
  `поверхность`; кнопка «Запустить» залита акцентом, во время запуска —
  спиннер и «Выполняется…».
- **Результат задания:** зачтено — зелёная рамка, метрика крупным
  моноширинным числом, цель рядом; не зачтено — нейтральная рамка, метрика и
  цель, диагностика харнесса; ошибка — красная рамка, трассировка в
  моноширинном блоке с прокруткой.
- **Графики** (uPlot): сетка `линии`, подписи `приглушённый`, серии из
  палитры на токенах (акцент первой серией).
- **Выноски** («Боль сервиса №N» и прочие blockquote/callout): фон
  `поверхность`, полоса 3px акцентом слева.
- **Код в тексте:** фон `поверхность`, JetBrains Mono, кнопка «копировать».
- **Ссылки-якоря у заголовков** (`heading-link`) — появляются при наведении.

### 4.6. Совместимость с JS

JS-блоки, viz-модули и `render.py` переписывают свои классы на утилиты, но
сохраняют все `data-*` атрибуты и структуру, на которую опираются тесты
(`data-kind`, `data-id`, `data-part`, `data-exercises`, `data-section`).
Viz `cow-pages` и `pymalloc-arenas` перекрашиваются на токены (CSS-переменные),
логика не меняется.

## 6. Риски

- **Динамические классы не попадут в сборку.** Правило полных литералов
  (§4.1) и тест на наличие классов в `app.css`.
- **Перевод разметки JS сломает блок незаметно** (браузера нет). Порядок
  работ: сначала шаблоны и общий каркас, затем по одному блоку с проверкой в
  Node и коммитом; автор проверяет в Firefox после каждой группы.
- **Удаление C-поддержки заденет общий механизм runner'а.** Grep-правило §3.1
  и полный прогон `make test-runner` после удаления.
